# SYSTEM_LITERARY_DICTION（系統符號 × 敘事文學 詞彙字典）

> **本檔目的**：解決「這本是文明/情感向硬科幻，不是系統文（lit-RPG）」的詞彙使用混亂。
> 統一規範**哪些工程師/系統術語可以用、哪些必須用文學詞替換**，避免後續章節在敘事主軸誤用 RPG 系統文語法破壞沉浸。

---

## 0. 核心鐵則

### 0.1 一句話原則

> **主控台/螢幕/標識場景 = 系統符號（保留 V11 等工程師術語）**。
> **敘事主軸（角色 POV、對白、章節標題、章節描述核心機制）= 文學詞（禁用 V11 等工程師術語）**。

### 0.2 為什麼要區分

- V11 讀者第一眼會想到「Windows 11」「Android 11」；中文讀「V 十一」是工程語言。
- 本書的調性是「文明 × 情感」向硬科幻，**不是**網遊數值流。
- 同一本書混用 RPG 術語（升級/版本/解鎖/預測）會破壞沉浸。
- V0–V9 系統提示（`【權限判定中】` 等）已建立「系統符號 = 冷冰冰的機器視角」的視覺語法；V10+ 不能讓 RPG 術語入侵敘事主軸。

---

## 1. 兩類詞彙定義

### 1.1 系統符號（保留用）

**判定條件**：讀者看到時會認知為「機器/系統/螢幕的輸出」，而非敘事者的語言。

**場景白名單**：
- 主控台顯示
- 螢幕標識 / 數據標頭
- 系統錯誤訊息
- 高維文明介入的提示框
- 探測器/航行體的感測報告

**範例（V9 末用過的合法寫法）**：
- ✅ 「主控台顯示 V11 標識」
- ✅ 「螢幕右上角浮現一行猩紅字樣：V11 共識臨界」
- ✅ 「航行體感測器回報 V11 頻段啟動」
- ✅ 角色讀到螢幕上的「V11 預測」字樣（讀者知道這是螢幕上的字，不是敘事者在說話）

### 1.2 敘事主軸（必須文學化）

**判定條件**：讀者會認知為「敘事者在描述故事」，而非「螢幕在輸出」。

**場景黑名單（禁用系統符號）**：
- 章節標題（**標題開頭禁用 V11/版本號**）
- 章節開頭的「本章核心機制」一句
- 角色 POV 的內心獨白
- 角色對白（除非對白內容是讀螢幕上的字）
- 環境描寫中的氣氛營造
- 章節結尾鉤子句

**必須用文學詞的常見位置**：
- 機制名稱
- 階段名稱
- 解鎖事件
- 路線名稱
- 升級/降級/觸發的描述

|---|---|---|

| V11 解鎖 | 文明躍遷 / 標識亮起 / 跨階段開啟 | 解鎖事件 |

| V11 路線 | 升級型路線 / 延展型路線 / 融合型路線 | 路線名 |
| V10.5 完全體 | 完全體 / 共識度 97.4% 完全體 | 階段名 |

| V10.5 三倍效率 | 共識臨界三倍效率 / 文明共振三倍效率 | 機制名 |
| 升級型 V11 | 升級型路線 | 路線名 |
| 延展型 V11 | 延展型路線 | 路線名 |
| 融合型 V11 | 融合型路線 | 路線名 |
| 版本更新 | 系統演進 / 標識更新 | 事件描述 |
| 規則重新編譯 | 規則重組 / 因果線重組 | 機制描述 |
| 因果反轉感知完全展開 | 因果反轉感知完全展開（**這個保留**——「感知」是角色能力詞，不是系統符號）| 角色能力 |
| 規則層全域震盪 | 規則層全域震盪（**這個保留**——「震盪」是物理感詞，不是版本號）| 場景描述 |

### 2.1 為什麼「因果反轉感知」「規則層全域震盪」可以保留

- 「感知」是角色的感官能力（**角色詞**），不是系統版本號。
- 「震盪」是物理現象詞（**物理詞**），不是工程術語。
- 判斷原則：**如果這個詞在字典裡查不到「V 幾」或「版本」的意思，就不是系統符號。**

## 3. 場景判斷矩陣

### 3.1 系統符號場景（V11 等可用）

| 場景 | 判斷特徵 | 範例 |
|---|---|---|
| 主控台 | 角色盯著螢幕 | 林燼在主控台前看到 V11 標識浮現 |
| 探測器感測 | 數據回傳 | 航行體回報：V11 頻段啟動 |
| 系統錯誤訊息 | 紅字閃爍 | 螢幕跳出：V11 共識臨界 |
| 探測隊回報的螢幕截圖 | 影像資料 | 螢幕上顯示：V11 路線預測 |
| 角色讀螢幕 | 角色在「讀」 | 蘇嵐盯著螢幕上的 V11 字樣 |

### 3.2 敘事主軸場景（V11 等禁用）

| 場景 | 判斷特徵 | 應改為 |
|---|---|---|
| 章節標題 | 標題是讀者第一眼看到的 | 「共識臨界」/「三路線驗證」/「文明躍遷」 |
| 章節開頭 | 「本章核心機制」一句 | 用文學詞描述本章機制 |
| 角色 POV 內心 | 角色在想什麼 | 用角色語言描述狀態 |
| 角色對白 | 角色在說話（不是讀螢幕） | 用文學詞 |
| 環境描寫 | 場景氣氛 | 用物理/感官詞 |
| 章節結尾鉤子 | 留懸念句 | 用文學詞 |

## 4. 判斷流程圖

```
這個詞要寫進小說？
│
├─ 是「主控台/螢幕/標識/數據」場景？
│  ├─ 是 → 系統符號場景，V11 等可保留
│  └─ 否 → 進入下一個判斷
│
├─ 是角色讀螢幕的轉述/轉引？
│  ├─ 是 → 可保留 V11（讀者知道是螢幕上的字）
│  └─ 否 → 進入下一個判斷
│
├─ 是章節標題/章節描述核心機制/章節結尾鉤子？
│  ├─ 是 → 必須用文學詞
│  └─ 否 → 進入下一個判斷
│
├─ 是角色 POV 內心/角色對白（不是讀螢幕）？
│  ├─ 是 → 必須用文學詞
│  └─ 否 → 進入下一個判斷
│
└─ 是物理詞/角色能力詞/場景詞？
   ├─ 是 → 可保留
   └─ 否 → 預設用文學詞
```

## 5. V10+ 適用規則

### 5.1 章節標題強制規則

**任何新章節的標題不允許以「V 數字」開頭**：

- ❌ 「V11 階段開始」 / 「V10.5 完全體」 / 「V12 解鎖」
- ✅ 「共識臨界」 / 「完全體」 / 「三路線驗證」 / 「文明躍遷」

### 5.2 章節核心機制描述規則

章節開頭的「本章核心機制」一句必須用文學詞：

- ❌ 「本章描述 V11 階段開始」
- ✅ 「本章描述主機跨入下一個規則層；共識度達標，標識亮起」

### 5.3 角色對白規則

**對白中 V11 等出現的合法情境**：
- 角色在讀螢幕（讀者知道是螢幕上的字）
- 角色在引用過往事件（已經發生過的事實）

**對白中 V11 等非法的情境**：
- 角色在描述未發生事件的機制
- 角色在解釋當下狀態
- 角色在規劃未來行動

### 5.4 既有文本處理

- **V9 末已落定的 120 處 V11 用法不追溯修改**（避免大規模返工）。
- **V10 起所有敘事主軸重新包裝**。
- 若讀者反饋 V9 末的 120 處太跳戲，可在 V11+ 卷做「主控台/螢幕」場景的整合修訂（不必改 V9 末）。

## 6. 違規檢查清單

寫完一章後，用以下清單 grep：

```bash
# 1. 章節標題開頭禁用 V 數字
grep -n '^# V[0-9]' 01_NOVEL_CONTENT/XX_第X卷_XXX/*.md

# 2. 段落開頭禁用 V 數字（粗篩）
grep -n '^V[0-9]' 01_NOVEL_CONTENT/XX_第X卷_XXX/*.md

# 3. 角色對白中禁用 V11（用上下文判斷；不能全 grep）
#   例外：對白內容是讀螢幕（"螢幕寫著 V11..."）

# 4. 章節描述「本章核心機制」禁用 V11
grep -B 1 -A 1 '核心機制' 01_NOVEL_CONTENT/XX_第X卷_XXX/*.md
```

## 9. 例外清單

以下詞雖是「版本號」或「階段名」，但**不需用文學詞替換**：

- **H-Compute / L-Compute**：資源類型名稱（V0–V14 主機版本配套），是**類型詞**不是版本號，**保留**。
- **碎片 / 燃料**：物質類型，**保留**。
- **阿卡夏熔爐**：地名/裝置名，**保留**。
- **V0–V9 的系統提示範本**（`【權限判定中】` 等）：是**系統符號**，主控台/螢幕場景，**保留**。
- **因果視覺 / 因果反轉感知**：角色**能力詞**，不是版本號，**保留**。
- **規則層 / 規則霧**：物理/概念詞，**保留**。

判斷原則：
> **類型名 / 能力名 / 物理詞 / 系統符號場景** → 保留。
> **版本號 / 階段名 / 解鎖事件 / 路線名（V11 前綴）** → 文學化。
