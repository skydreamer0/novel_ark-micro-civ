# 專案紀錄 #2026-06-04-01：文學化鐵則建立（V11 系統文語法問題）

## 1. 問題

V9 末 Ch.327-330 在 120 處使用了「V11」這個術語（章節標題、角色對白、系統標識等多種場景）。
用戶在 V10 brief 確認階段批評：「**對阿應該是這樣才對怎會直接去寫階段又不是系統文**」。

**問題本質**：本書調性是「文明 × 情感」向硬科幻，**不是**網遊數值流（lit-RPG / 系統文）。
V11 等工程師術語是 RPG 系統文語法：
- 中文讀「V 十一」是工程語言
- 讀者第一眼會想到「Windows 11」「Android 11」
- 視覺跳戲，破壞沉浸
- 跟既有的 `【權限判定中】` 等系統符號語法混淆（後者是「冷冰冰的機器視角」，前者是「RPG 升級語法」）

## 2. 解決方案

建立**主字典檔 + 嵌入式引用**的兩層結構：

### 2.1 主字典檔（新建）
- `02_PROJECT_DATABASE/SYSTEM_LITERARY_DICTION.md`
  - 核心鐵則（一句話原則 + 為什麼要區分）
  - 兩類詞彙定義（系統符號 vs 敘事主軸）
  - 替換對照表（V10+ 適用）
  - 場景判斷矩陣
  - 判斷流程圖
  - V10+ 適用規則
  - 違規檢查清單
  - 違規/合法案例對照
  - 例外清單（H-Compute/能力詞/物理詞 不需替換）
  - 修訂紀錄

### 2.2 嵌入式引用（修改既有檔案）
- `STYLE.md` §3.5 新增：系統符號 vs 敘事主軸詞彙（簡述 + 引用主檔）
- `RULES.md` §3.4 新增：系統符號 vs 敘事主軸鐵則（強制規則 + 引用主檔）
- `CANON_power.md` §8.3 加備註：敘事中以文學詞呈現，完整規則見 SYSTEM_LITERARY_DICTION.md

### 2.3 專案紀錄（本檔）
追蹤：
- 問題起源
- 解決方案落地
- 修法決策
- 違規清單（V9 末 120 處）
- 後續檢查項
- 影響的章節/VOL/brief

## 3. 修法決策

| 決策 | 理由 |
|---|---|
| V9 末 120 處 V11 不追溯 | 避免大規模返工；保留為 V9 末的「系統視角」標記 |
| V10 起敘事主軸重新包裝 | V10 是新開始；新章節遵守新規則 |
| 章節標題強制不允許「V 數字」開頭 | 標題是讀者第一眼看到的，影響最直接 |
| 主控台/螢幕/標識場景保留 V11 | 系統符號場景是「冷冰冰的機器視角」既有語法，統一 |
| 對白中 V11 需上下文判斷 | 角色讀螢幕 → 合法；角色在描述未來/解釋當下 → 非法 |
| 創建獨立主字典檔 | 集中管理，避免散落在多個檔案造成不一致 |
| STYLE/RULES/CANON_power 嵌入引用 | 讓所有 subagent 在載入核心檔時就看到引用，強化約束 |
